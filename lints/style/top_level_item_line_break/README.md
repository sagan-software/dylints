# top_level_item_line_break

## What it does

Checks items in the crate root and in modules, and warns when an item starts on
the same line where the previous item ends. One line break is enough; a blank
line is not required.

## Why is this bad?

Two items on one line hide the boundary between them. Readers scanning the
left edge of the file miss the second item, and diffs that touch either item
show both.

## Known problems

Items inside functions, traits, and `impl` blocks are not checked. Items
generated by macros and items removed by `cfg` are not checked.

## Example

```rust
fn first() {} fn second() {}
```

## Use instead

```rust
fn first() {}
fn second() {}
```

# top_level_item_line_break

## What it does

Checks items in the crate root and in modules, and warns when an item starts on
the same line where the previous item ends. An item starts at its first outer
attribute or doc comment. One line break is enough; a blank line is optional.
The machine-applicable fix moves the item to a new line with the same
indentation.

## Why is this bad?

Two items on one line hide the boundary between them. Readers scanning the
left edge of the file miss the second item, and diffs that touch either item
show both.

## Known problems

The lint skips items inside functions, traits, and `impl` blocks. It also skips
items generated by macros and items removed by `cfg`.

## Example

```rust
fn first() {} fn second() {}
```

## Use instead

```rust
fn first() {}
fn second() {}
```
